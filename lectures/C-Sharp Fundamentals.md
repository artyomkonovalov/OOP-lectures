# Структура программы

<a name="section-002"></a>

## Overview

<a name="section-003"></a>

### Типичная структура программы на C-Sharp
Программа состоит из ключевых блоков:
* namespace - организовывают типы
* types - определяют поведения и data
	* class
	* 
	* struct
	* interface
	* enum
	* delegate
* statements/expressin - обеспечивают работу в runtime

<a name="section-004"></a>

### Выбор типа приложения
Когда создаёшь приложение на C# нужно сделать два независимых выбора о структуре проекта:
1. File-based / Project-based
	* file-based: запускаются из одного .cs файла, не требуют файла проекта
	* project-based: используют .csproj файл и охватывают множество исполняемых файлов
2. Top-level statements / Main method
	* Top-level statements: позволяют писать код прямо с начала файла
	* Main method: оборачивает точку входа явным статическим методом

<a name="section-005"></a>

#### File-based apps
* подходят для написания простых скриптов, утилит командной строки, экспериментов
* весь код хранится в одном файле
* можно запустить скрипт: `dotnet (run) hello-world.cs`
* если добавить в начало файла строчку `#!/usr/bin/env dotnet` можно будет запускать файл напрямую командой `./hello-world.cs` (для Unix систем)
* поддерживают весь синтаксис C# и директивы препроцессора
* структура проекта (один файл):
```
my-app/
└── hello-world.cs
```

<a name="section-006"></a>

#### Project-based apps
* используют .cproj файл и команды .NET CLI:
	* `dotnet new`
	* `dotnet build`
	* `dotnet run`
* используются, когда проект состоит из нескольких файлов или для него нужны особенный build
* структура проекта:
```
my-app/
├── my-app.csproj
├── Program.cs
├── Models/
│   └── Person.cs
└── Services/
    └── GreetingService.cs
```

Возможно [конвертировать](../links/%D0%BA%D0%BE%D0%BD%D0%B2%D0%B5%D1%80%D1%82%D0%B8%D1%80%D0%BE%D0%B2%D0%B0%D1%82%D1%8C.md) file-based -> project-based

<a name="section-007"></a>

#### Top-level statements vs `Main` method
В проекте может быть ТОЛЬКО ОДИН файл с top-level statements. Тогда точка входа в проект - первая строчка такого файла
В остальном оба способы равнозначны как для file-based, так и для project-based программ:
```
Console.WriteLine("Hello, World!");
```
равносильно
```
class Program
{
    static void Main(string[] args)
    {
        Console.WriteLine("Hello, World!");
    }
}
```

<a name="section-008"></a>

### Expressions and statements

<a name="section-009"></a>

#### Expressions - создают значения
* Значение литерала: `42`
* Арифметическое выражение: `x + y`
* Вызов метода, возвращающего значение:  `Math.Max(a, b)`
* Условное выражение: `condition ? trueVal : falseVal`
* Создание объекта: `new Person("John")`

<a name="section-010"></a>

#### Statements - совершают действия и обычно заканчиваются ';'
* Объявление: `int x`;
* Объявление и определение: `int x = 69`;
* Метод, вызывающий statement: `Console.WriteLine(123);`
* Условие: `if (condition) { /* code */ }`
* return: `return 64;`

<a name="section-011"></a>

## Namespaces and using directives

<a name="section-012"></a>

### Объявление namespace
`namespace` объединяет типы в именованную группу. Любой тип должен принадлежать какому-либо `namespace`. `namespace`'ы отражают директорную структуру проекта (одна папка в другой). Позволяют избежать коллизии имён

<a name="section-013"></a>

### File-scoped namespace
`namespace MyApp.Models` - распространяется на весь файл (может быть только один на весь файл)
Наиболее рекомендуемый стиль `namespace`'ов

<a name="section-014"></a>

### Block-scoped namespace
`namespace MyApp.Models {}` - собирает в пространство имён только часть в {}.
Используется, когда в файле нужно определить несколько пространств имён - редко!!
Предпочтительнее использовать file-scoped namespace

<a name="section-015"></a>

### Using-директивы
Пишутся в начале файла, импортируют нужный `namespace` и позволяют обращаться к его типам по их простым именам:
```
System.Console.WriteLine(123)
```
=>
```
using System;
Console.WriteLine(123);
```

`using` распространяется на один файл. 
Если в любом файле проекта использовать `global using`, то к его типам можно будет обращаться напрямую из любого места проекта. Обычно создают специальный файл `GlobalUsings.cs`

<a name="section-016"></a>

### Неявные using
Большинство стандартных `using` неявно импортируются в проект:
* `System`
* `System.Collections.Generic`
* `System.IO`
* `System.Linq`
* `System.Threading`
* `System.Threading.Tasks`
Это отключается в настройках проекта `ImplicitUsings`

<a name="section-017"></a>

### static using
позволяют использовать статические методы типов без указания имени типа:
```
using static System.Math;

namespace MyApp.Utilities;

class CircleCalculator
{
    public static double CalculateArea(double radius) => PI * Pow(radius, 2);

    public static double CalculateCircumference(double radius) => 2 * PI * radius;
}
```

<a name="section-018"></a>

### Type and namespace alias
Алиас `using` можно использовать для создания короткого наименования типа или `namespace`. Это удобно для длинных шаблонных типов, устраняет конфликт имён и улучшает читаемость кода.
```
using CustomerList = System.Collections.Generic.List<MyApp.Models.Customer>;
```
Начиная с C# 12 можно создавать алиасы любого типа, в том числе `tuple` и `pointer types`
```
using Point = (double X, double Y);
```

<a name="section-023"></a>

## Top-level statements
* Можно использовать `using` директивы - они должны быть ДО кода в файле с top-level statements
* top-level statements неявно находятся в глобальном пространстве имён. В таком файле МОЖНО объявлять `namespace` и другие типы, но это должно быть написано ПОСЛЕ кода top-level statements
* Можно обратиться к переменной `args` чтобы получить доступ к любому аргументу командной строки. `args` никогда не равно `null`, но его `.Length` может быть равно 0, если не передано ни одного аргумента командной строки

<a name="section-024"></a>

## Метод Main() и аргументы командной строки
Когда мы запускаем приложение на C#, вызывается метод `Main`, который служит точкой старта для приложения.
Программа на C# может иметь только одну точку старта. Если объявлено больше одного класса с методом `Main()`, необходимо использовать опцию компилятора `StartupObject`
Программа завершается, когда `Main()` что либо возвращает.
Правила определения метода `Main()`:
* Нужно определить метод `Main()` внутри структуры или класса, который может быть `static`
* `Main()` должен быть `static`
* `Main()` может иметь любой модификатор доступа
* `Main()` может возвращать `void`, `int`, `Task` или `Task<int>`
* `Main()` можно присвоить модификатор `async` ТОГДА И ТОЛЬКО ТОГДА, когда метод возвращает `Task` или `Task<int>`.
* Можно добавить необязательный аргументы `string[] args`, который будет хранить аргументы командной строки. В отличие от C++, не хранит имя программы как первый аргумент, но оно является первым элементом метода `GetCommandLineArgs()`
Можно конвертировать аргументы типа `string` в другие типы, используя `Parse` или `Convert`:
```
long num = long.Parse(args[0]);
```

# Система типов

<a name="section-026"></a>

## Overview
C# - строго типизированный язык. Компилятор поддерживает type safety, проверяя, что все операции, в которых используется код, верны для типов, с которыми их применяют. Type safety ловит ошибки на этапе компиляции.
Так, в частности, нельзя сложить `bool` и `int` (в C# `bool` не приводится к `int`):
```
// Error. Operator '+' cannot be applied to operands of type 'int' and 'bool'.
// int c = a + test;
```

<a name="section-027"></a>

### Объявление переменных с помощью типов
Во время объявления переменной можно явно указать тип или использовать `var`, чтобы компилятор определил её тип по присваиваемому значению:
```
// Explicit type:
int count = 10;
double temperature = 36.6;

// Compiler-inferred type:
var name = "C#";
var items = new List<string> { "one", "two", "three" };
```

<a name="section-028"></a>

### Встроенные и кастомные типы
C# предоставляет встроенные типы для стандартных данных: целых чисел, чисел с плавающей точкой, `bool`, `char` и `string`. Их можно использовать без дополнительных using'ов.
Так же можно создавать свои типы при помощи следующих конструкций:
* Class - ссылочные типы для моделирования поведения и сложных объектов. Поддерживают наследование и полиморфизм
* Struct - значимые типы для небольших, легковесных данных. Каждая переменная хранит свою копию
* Record - класс или структура со сгенерированными компилятором сравнением по значению, ToString, и недеструктивной мутацией посредством выражений
* Interface - контракт, определяющий члены класса или структуры
* Enumerations - именованные множества интегральных констант
* Tuples - легковесные структурные типы, группирующие связанные значения без определения имени типа
* Generics - типопараметризуемые шаблоны, такие как `List<T>` и `Dictionary<TKey, TValue>`, предоставляющие безопасность типов при использовании одной и той же логики для различных типов

<a name="section-029"></a>

### Ссылочные и значимые типы
Любой тип в C# является *ссылочным* или *значимым*, что определяет, как объекты хранят информацию и как работает присваивание

<a name="section-030"></a>

#### Value Types (Значимые типы)
Хранят данные напрямую. При присваивании нового объекта объекту значимого типа, данные копируются в рантайме. При этом изменения одного объекта не затрагивают другой. Представители:
* Structs
* Enums
* built-in numeric types

<a name="section-031"></a>

#### Reference Types (Ссылочные типы)
Хранят ссылку на объект, созданный на куче. Приcваивание ссылочного объекта другому ссылочному объекту работает так, что оба объекта ссылаются на одни и те же данные. Изменения одного объекта приводит к изменению остальных. Представители:
* Classes
* Arrays
* Delegates
* Strings
Все типы автоматически наследуются от `System.Object`. Значимые типы наследуются от `System.ValueType`, который наследуется от `object`. Такая единая иерархия называется **Common Type System (CTS)**.

<a name="section-032"></a>

### Выбор используемого типа

<a name="section-033"></a>

#### Tuple
Временная группа значений, которой не нужны имя и прописанное поведение.

<a name="section-034"></a>

#### struct или record struct
Небольшие данные (64 байта и меньше), семантика значимого типа или иммутабельность. Record structs, сравнение по значению, выражения с `with`

<a name="section-035"></a>

#### record class
Прежде всего данные с равенством по значению, ToString и недеструктивным изменением (nondestructive mutation). Поддерживает наследование

<a name="section-036"></a>

#### class
Сложное поведение, полиморфизм или изменяемое состояние. Большинство кастомных типов - классы

<a name="section-037"></a>

#### interface
Контракт, который несвязанные типы могут реализовать. Определяет скорее возможности, нежели отдельную сущность

<a name="section-038"></a>

#### enum
Фиксированное множество именованных констант, таких как статус-коды и опции

Возможна реализации при помощи более чем одного варианта!

<a name="section-039"></a>

## Встроенные типы

<a name="section-040"></a>

### Числовые типы
* `int` - 32битные целые числа
* `long` - 64битные целые числы
* `short`, byte - меньшие значения
* `double` - обычные числа с плавающей точкой (без особого суффикса)
* `float` - когда память ограничена (суффикс f)
* `decimal` - для точного десятичного приближения (например, для финансовых вычислений) (суффикс m)

<a name="section-041"></a>

### Беззнаковые типы
Можно использовать `uint`, `ulong`, `ushort`, для представления данных, которые не могут быть отрицательными, таких как размер файла и т.д. На практике, многие приложения используют `int` и `long` даже для только положительных значений, так как знаковые типы стандартны для .NET APIs.

<a name="section-042"></a>

### Native-sized integers
`nint` и `nuint` представляют размер, соответствующий стандартному размеру указателей в операционной системе: 32 бита на 32-битной и 64 на 64-битной. Это нужно скорее для низкоуровнего программирования.

<a name="section-043"></a>

### `bool`, `char`, `string`
Кроме числовых, C# представляет 3 другие часто используемые типы:
* `bool` - хранит `true` или `false`. Используется в условиях и логических выражениях 
* `char` - хранит одиночный символ Unicode, представляется в `''`
* `string` - хранит последовательность символов в `""`. Строки неизменяемые. После создания строки нельзя менять её содержимое, а операции, которое это делают, на самом деле создают новую.

<a name="section-044"></a>

### Литералы
* Целочисленные:
	* десятичные: `42`
	* 16-ричные: `0x2A`
	* бинарные: `0b_0010_1010`
* Для чисел с плавающей точкой:
	* double: стандартно `3.14`
	* float: `3.14f`
	* decimal: `3.14m`
* Символьные: `'A'`
* Строковые:
	* обычные `"hello"`
	* буквальные (игнорируют спецсимволы): `@"C:\path"`
	* сырые `"""..."""`
	* интерполированные `$"value: {x}"`
* булевые: `true` / `false`
* `null` - отсутствие значения для ссылочных типов и нулевое значение для значимых
* `default` - представляет дефолтное значение любого типа

<a name="section-045"></a>

### `default` выражения
* `0` для числовых типов
* `false` для `bool`
* `null` для ссылочных типов
Очень полезно в generic-коде, когда мы не знаем конкретного типа и не можем захардкодить дефолтное значение

<a name="section-046"></a>

### Target-typed `new` expressions
Когда тип уже известен из контекста, можно опустить тип в `new` выражении. Компилятор сам вычислит его по параметру метода или из объявления. Можно использовать везде, где компилятор сам способен определить тип, включая аргументы методов и возвращаемые значения.

<a name="section-047"></a>

### `dynamic` тип
Такой тип обходит проверку типов в компайлтайме. Вместо этого все операции с таким типом происходят в рантайме. Желательно избегать такого в обычном коде, так как это лишает type-safety. При этом можно использовать с COM APIs и динамическими языками, где тип на этапе компиляции заранее не известен.


<a name="section-048"></a>

## Classes
Класс - ссылочный тип, который определяет поведение объектов. Когда создаётся переменная классового типа, она хранит ссылку на объект, выделенный на куче. Сам по себе объект в переменной не хранится. При присваивание объекта класса другой переменной, копируется ссылка на этот объект, так что оба будут указывать на одно и то же. Классы - наиболее стандартный способ определения типа в C#. Использовать их нужно когда необходимо сложное поведение, наследование или разделение логики между ссылками.

<a name="section-049"></a>

### Когда использовать класс
* Тип имеет сложное поведение или поддерживает мутабельность
* Необходимо наследование для создания базового класса с различными специализациями, чтобы создать наследника, расширяющего функционал родителя.
* Образец отражает разделяемую сущность, а не объекты, которые хранят равные значения. Два объекта ссылаются на одно и то же, и изменения должны быть синхронизированы.
* Тип тяжёлый или долгоживущий, так же нужно, чтобы он аллоцировался именно на куче и поддерживал ссылочную семантику

<a name="section-050"></a>

### Объявление класса
Определение класса происходит при помощи ключевого слова `class` после которого следует имя типа. Опциональный оператор доступа контролирует видимость класса. По умолчанию он `internal`.
Тело класса содержит *поля*, *свойства*, *методы* и *события*, которые вместе называются **членами класса**

<a name="section-051"></a>

### Создание объектов
Класс определяет тип, но не сам объект. Создание объекта происходит при помощи ключевого слова `new`.
```
var customer = new Customer("Allison");
Console.WriteLine(customer.Name); // Allison
```
Переменная `customer` хранит ссылку, а не сам объект. Можно создать ещё одну переменную, указывающую на тот же объект. Изменения в одной переменной отразятся и на другой:
```
var c1 = new Customer("Grace");
var c2 = c1; // both variables reference the same object

c2.Name = "Hopper";
Console.WriteLine(c1.Name); // Hopper — c1 sees the change made through c2
```
Разделение владением объекта по ссылке - одно из отличий класса от структуры. В структурах присваивание копирует данные. Более важно, что классы поддерживают наследование. Можно строить иерархии, где классы-наследники переиспользуют и специализируют поведение базового класса. Структуры не могут участвовать в иерархиях наследования. 

<a name="section-052"></a>

### Конструкторы и инициализация
Когда создаётся объект класса, хочется, чтобы его поля и свойства содержали полезные значения.  Существует несколько способов это реализовать

<a name="section-053"></a>

#### Инициализация полей
устанавливает дефолтное значение прямо на этапе объявления
```
public class Container
{
    private int _capacity = 10;
}
```
так мы указываем стандартное значение, в отличие от других способов

<a name="section-054"></a>

#### Параметры конструктора
требует от вызывающего предоставить параметры
```
public class Container
{
    private int _capacity;

    public Container(int capacity) => _capacity = capacity;
}
```

<a name="section-055"></a>

#### Primary-конструктор
начиная с C#12 можно добавить параметры прямо к определению класса. Эти параметры будут видны в теле класса:
```
public class Container(int capacity)
{
    private int _capacity = capacity;
}
```

<a name="section-056"></a>

#### `required-свойства`
заставляют вызывающего указать значения соответствующих свойств при создании объекта:
```
public class Person
{
    public required string FirstName { get; set; }
    public required string LastName { get; set; }
}
```
```//
var person = new Person { FirstName = "Grace", LastName = "Hopper" };
Console.WriteLine($"{person.FirstName} {person.LastName}"); // Grace Hopper
```

<a name="section-057"></a>

### Статичные классы
`static` классы не могут быть созданы и содержат только статичные члены. Их стоит использовать для организации утилит-методов, которые не оперируют с информацией конкретного объекта.
```
static class MathHelpers
{
    public static double CircleCircumference(double radius) =>
        2 * Math.PI * radius;
}
```
```
double circumference = MathHelpers.CircleCircumference(5.0);
Console.WriteLine($"Circumference: {circumference:F2}"); // Circumference: 31.42
```
К таким классам относятся в частности `Math` и `Console`. Статический класс неявно ограничен: от него нельзя наследоваться или создавать его объекты

<a name="section-058"></a>

### Инициализатор объектов
позволяет устанавливать свойства на этапе создания объекта без написания конструктора для каждой комбинации значений:
```
class ConnectionOptions
{
    public string Host { get; init; } = "localhost";
    public int Port { get; init; } = 80;
    public bool UseSsl { get; init; }
}
```
```
var options = new ConnectionOptions
{
    Host = "db.example.com",
    Port = 5432,
    UseSsl = true
};
Console.WriteLine($"{options.Host}:{options.Port} (SSL: {options.UseSsl})");
// db.example.com:5432 (SSL: True)
```
Инициализаторы объектов работают с любыми доступными свойствами, которые имеют `set` или `init` аксессоры. Они естественным образом сочитаются с `required` свойствами и с конструкторами, которые требует какие-нибудь аргументы, в то время как такие инициализаторы устанавливают значения других.
Если свойство - коллекция, можно использовать специальные Collection expressions.


<a name="section-059"></a>

### Наследование
Класс может наследоваться от одного базового класса и реализовывать множество различных интерфейсов. Классы-наследники наследуют все члены базового класса кроме конструкторов.
